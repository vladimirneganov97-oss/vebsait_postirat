# Сайт графика стирки

ASP.NET Core 8 + SQLite.

## Безопасность аккаунтов

- У каждого пользователя есть уникальный **ID аккаунта**.
- Вход выполняется по ID + паролю, поэтому имя, фамилия и комната не используются как секрет авторизации.
- Пароли никогда не сохраняются в открытом виде — используется `PasswordHasher`.
- В базе хранится только хэш пароля.
- В админке нельзя посмотреть настоящий пароль пользователя: в базе хранится только хэш. Администратор может задать новый пароль и увидеть его до сохранения кнопкой с глазом.
- Формы защищены antiforgery-токенами.
- Сессионная cookie имеет `HttpOnly` и `SameSite=Strict`; в Production она требует HTTPS.
- Добавлены базовые security headers.
- Для админского пароля используется переменная окружения `LAUNDRY_ADMIN_PASSWORD`.

## Лимит стирок

По умолчанию каждый пользователь может забронировать **2 стирки за календарную неделю**.

Администратор может изменить лимит отдельно для каждого пользователя (от 0 до 50).

## Подключение с телефона и других устройств по Wi-Fi

### Вариант 1 — обычный `dotnet run`

Проект для обычного запуска настроен на адрес `10.201.95.97:5000`:

```text
http://10.201.95.97:5000
```

Узнайте IPv4 компьютера:

```powershell
ipconfig
```

Например, если у ПК адрес:

```text
192.168.1.25
```

то с телефона в той же Wi-Fi сети можно открыть:

```text
http://10.201.95.97:5000
```

Если Windows Firewall спросит разрешение для .NET, разрешите входящие подключения в частной сети.

Если телефон не подключается, можно разрешить порт вручную в PowerShell **от имени администратора**:

```powershell
New-NetFirewallRule -DisplayName "Laundry Site 5000" -Direction Inbound -Protocol TCP -LocalPort 5000 -Action Allow -Profile Private
```

Для Docker-порта:

```powershell
New-NetFirewallRule -DisplayName "Laundry Site 8080" -Direction Inbound -Protocol TCP -LocalPort 8080 -Action Allow -Profile Private
```

Можно также явно запустить:

```powershell
dotnet run --urls "http://10.201.95.97:5000"
```

### Вариант 2 — Docker

Docker Compose публикует приложение на порт `8080`:

```text
http://IP_КОМПЬЮТЕРА:8080
```

Например:

```text
http://192.168.1.25:8080
```

Для этого:

```bash
docker compose up -d --build
```

## Важное предупреждение про Wi-Fi и безопасность

Адрес `http://10.201.95.97:5000` или `:8080` — это **HTTP**, а не HTTPS. Для домашней/учебной сети это удобно, но пароль при таком подключении не защищён шифрованием на уровне HTTP.

Если сайт используется за пределами доверенной локальной сети или на нём есть реальные пользовательские данные, используйте HTTPS. Для интернет-развёртывания в проекте уже есть Caddy и автоматический HTTPS через домен.

Не открывайте порт `5000` или `8080` в интернет без HTTPS и дополнительной защиты.

### Если сайт не открывается с другого устройства
1. Убедитесь, что компьютер и телефон подключены к одной Wi-Fi сети.
2. На компьютере выполните `ipconfig` и найдите IPv4 активного Wi-Fi/Ethernet адаптера.
3. Запустите сайт. В обычном режиме он доступен только по адресу `http://10.201.95.97:5000`. В Docker контейнер слушает порт 5000, а наружу он публикуется на порт 5000.
4. Разрешите входящий TCP-порт в Windows Firewall для профиля Private.
5. На другом устройстве откройте `http://10.201.95.97:5000` или `http://IP_КОМПЬЮТЕРА:8080`.
6. Не используйте `localhost` или `127.0.0.1` на телефоне: они указывают на сам телефон.

### Важно про пароль пользователя
Получить из `PasswordHash` исходный пароль нельзя: это одностороннее хэширование. Хранить отдельное поле с настоящими паролями только ради просмотра в админке небезопасно, поэтому проект этого не делает.

## Регистрация

После регистрации пользователь получает уникальный ID, например:

```text
A81F03D9B7C2
```

Его нужно сохранить. Для следующего входа используется:

```text
ID аккаунта + пароль
```

Одинаковая комбинация имени, фамилии и комнаты не может создать второй аккаунт.

## Админ-панель

Адрес:

```text
/Admin/Login
```

Пароль задаётся через:

```powershell
$env:LAUNDRY_ADMIN_PASSWORD="сложный_пароль"
dotnet run
```

В админке можно:

- просматривать ID пользователей;
- видеть количество использованных стирок за текущую неделю;
- менять недельный лимит конкретного пользователя;
- задавать новый пароль пользователю;
- удалять аккаунты;
- освобождать бронирования;
- менять день и время слотов.

## База данных

SQLite:

```text
Data/laundry.db
```

Не удаляйте файл, если нужно сохранить пользователей и бронирования.

Для Docker база находится в volume `laundry_data`.
